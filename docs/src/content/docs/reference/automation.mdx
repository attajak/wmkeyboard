WM Keyboard listens for five broadcast intents that change the layout from
outside the keyboard. Send them from a computer with `adb`, or from an
automation app such as Tasker, MacroDroid or Automate, to put French on when
you open one app and Bengali when you open another, or to switch with a
home-screen shortcut.

Every intent chooses among the layouts you already turned on under
<SettingsPath path="Languages & layouts" />, the same set the 🌐 key and the
spacebar swipe move through. An intent can't add a layout, remove one, or
reach one you left off. It reads no text and types nothing.

## The intents

All five go to the package `com.wasimaster.wmkeyboard`.

| Action | Extra | Does |
|---|---|---|
| `com.wasimaster.wmkeyboard.action.SET_LAYOUT` | `layout`: a layout id or name | Switches to that layout. |
| `com.wasimaster.wmkeyboard.action.SET_LANGUAGE` | `language`: a language id, locale or name | Switches to a layout of that language. |
| `com.wasimaster.wmkeyboard.action.NEXT_LAYOUT` | none | Moves one layout forward in your switch order. |
| `com.wasimaster.wmkeyboard.action.PREVIOUS_LAYOUT` | none | Moves one layout back. |
| `com.wasimaster.wmkeyboard.action.LIST_LAYOUTS` | none | Changes nothing. Answers with the layouts you have on. |

Both extras are strings.

## Sending them with adb

Name the package with `-p`. Android 8 and newer do not deliver a broadcast to
an app that the sender doesn't name.

```sh
adb shell am broadcast -a com.wasimaster.wmkeyboard.action.SET_LANGUAGE -p com.wasimaster.wmkeyboard --es language fr
adb shell am broadcast -a com.wasimaster.wmkeyboard.action.SET_LAYOUT -p com.wasimaster.wmkeyboard --es layout builtin_avro
adb shell am broadcast -a com.wasimaster.wmkeyboard.action.NEXT_LAYOUT -p com.wasimaster.wmkeyboard
```

`am broadcast` prints the keyboard's answer. A switch that worked reads
`result=-1` and names the layout that is now active:

```
Broadcast completed: result=-1, data="builtin_french"
```

A request the keyboard can't carry out reads `result=0` and says why, for
example `no enabled layout is for the language "de"`.

### Finding the ids

Send `LIST_LAYOUTS` to see what you can switch to:

```sh
adb shell am broadcast -a com.wasimaster.wmkeyboard.action.LIST_LAYOUTS -p com.wasimaster.wmkeyboard
```

Each line holds a layout id, its language id and its name, separated by tabs,
in your switch order. A `*` marks the layout in use.

```
Broadcast completed: result=-1, data="* builtin_qwerty	en	QWERTY
  builtin_avro	bn	Avro phonetic"
```

## Sending them from Tasker

Tasker, MacroDroid and Automate each have an action that sends an intent. The
fields are the same in each. In Tasker:

1. Add the action **System › Send Intent**.
2. Set **Action** to `com.wasimaster.wmkeyboard.action.SET_LANGUAGE`.
3. Set **Extra** to `language:fr`.
4. Set **Package** to `com.wasimaster.wmkeyboard`.
5. Set **Target** to **Broadcast Receiver**.

Put the action in a task that an **App** profile starts, and the keyboard
changes language as that app opens. An automation app does not read the answer
the way `adb` does, so test a new name from `adb` first, or use a name you can
see on the Languages screen.

## How each one decides

- **`SET_LAYOUT`** takes the layout's id, such as `builtin_qwerty`. Case does
  not matter. It also takes the layout's name, such as `AZERTY`, but only when
  exactly one of your layouts has that name. When two share it, the request is
  refused, not guessed.
- **`SET_LANGUAGE`** takes a language id (`en`, `bn`, `bn_rom`), a locale
  (`en-US`, `bn_BD`), or the language's name in English or in the language
  itself (`French`, `Français`). A locale the keyboard has no exact match for
  falls back to its first part, so `fr-CA` finds French. When you have several
  layouts of the language on, the one you used last wins. When a layout of it is
  already in use, nothing changes.
- **`NEXT_LAYOUT` and `PREVIOUS_LAYOUT`** walk your switch order and wrap
  around at either end. They always use the plain order, even with
  **🌐 goes back to the last language** on, so an automation gets the same
  result every time.

## Details & edge cases

- **A switch is the same switch the 🌐 key makes.** A half-typed word is
  committed first, the suggestions change language at once, and the layout goes
  on your recently-used list. With **Remember language per app** on, the app you
  are typing in remembers it too.
- **The keyboard doesn't have to be open.** While WM Keyboard is your current
  keyboard, the switch lands straight away, even with the keys hidden. While a
  different keyboard is selected, the choice is saved and WM Keyboard opens on
  it the next time you use it.
- **Any app on the phone can send these.** They need no permission, because
  they can do no more than a spacebar swipe. The worst another app can do is
  change which of your layouts is showing.
- **Nothing happens before the first unlock after a restart.** Android keeps
  apps from receiving broadcasts until you unlock the phone once. From then on
  the intents work on the lock screen too.
- **To open a settings screen instead,** use a `wmkeyboard://` link. See
  [Deep links & launcher shortcuts](/reference/deep-links/).
